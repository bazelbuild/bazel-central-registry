# isaacsim

[Isaac Sim](https://github.com/isaac-sim/IsaacSim) does not ship Bazel build
files — it builds with premake and packman — so this module version supplies
them as an overlay on the upstream `v6.0.0` source tarball. Nothing in the
overlay patches Isaac Sim's own sources.

```bash
bazel build @isaacsim//:extensions             # the Apache-2.0 half
bazel run   @isaacsim//:isaacsim -- --no-window # Isaac Sim itself, headless
```

The v6.0.0 release carries no archive asset, so `source.json` points at the
GitHub-generated tag tarball and the BCR URL-stability check has to be waived
with a `@bazel-io skip_check unstable_url` comment on the PR.

## What the overlay contains

| Path | What it is |
| --- | --- |
| `MODULE.bazel`, `BUILD.bazel` | the module, its extension targets and run/test targets |
| `bazel/` | the build itself; `bazel/README.md` documents it in full |
| `bazel/source_exts.bzl` | GENERATED by `bazel/gen_source_exts.py` from the source tree |
| `bazel/exts_lock.json` | GENERATED by `bazel/gen_exts_lock.py`; pins the closed Kit packages |
| `tests/` | the `bcr_test_module`: a consumer of `@isaacsim` |

Both GENERATED files are reproducible from the release tarball plus a Kit
dependency resolution; `bazel/README.md` gives the exact commands.

## Why a closed dependency is fetched

Isaac Sim is an application on top of NVIDIA Omniverse Kit. The Kit kernel and
the `omni.*` extensions under it are closed and published only as prebuilt
packman archives — Isaac Sim's own build downloads exactly the same ones
(`deps/kit-sdk.packman.xml`). This module pins them by sha256 (the kernel in
`bazel/private/kit_repo.bzl`, the extensions in `bazel/exts_lock.json`) and
fetches them through a module extension. Of Isaac Sim's own 149 `isaacsim.*`
extensions, 108 are built from source here: every pure-Python one, the six whose
OmniGraph node databases this build generates, one whose vendored wheels come
from PyPI, and six with C++ — compiled against the headers the kernel package
ships plus the `openusd` and `physx` registry modules. The remaining 41 are
either recipes not written yet or extensions whose payload the source release
does not carry, and come from the same pinned archives.

Both repositories are lazy: `@isaacsim//:extensions`, the Apache-2.0 half,
downloads neither. Fetching the closure is a one-off but not a small one — about
8 GB of archives, 11 GB extracted, and the single largest of them
(`omni.isaac.ml_archive`, which is a bundled PyTorch) takes several minutes to
unpack on its own.

## Platforms

Linux x86_64 and aarch64 with glibc ≥ 2.35 (`manylinux_2_35`), which is what the
Kit kernel is published for. Targets that run Kit are
`target_compatible_with = ["@platforms//os:linux"]`; the source-built extensions
build anywhere.

## What CI can and cannot check

`presubmit.yml` builds the source-built extensions and runs Kit on its kernel
over all of them (`tests:kit_discovers_extensions_test`) — no GPU, no closed
extension closure, ~80 MB of downloads.

Starting Isaac Sim proper needs an RTX GPU and the full ~8 GB closure, which
shared CI has neither of, so `tests:isaacsim_launch_test` is tagged `manual`.
On a machine with a GPU:

```bash
bazel test @isaacsim//:launch_test          # or //:isaacsim_launch_test in tests/
```
